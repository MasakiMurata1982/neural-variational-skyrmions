# MANIFEST — figure / table → script → data

Figure and table numbers follow the paper (figures 1–6 and tables 1–12). All analysis scripts read `data/runs_reported.csv` (1,398 reported runs, the 20 rows of table 12; a CSV with the same columns can be given as the first argument) unless a JSON in `data/derived/` is named.
The scripts in `code/analysis/` find their inputs through the block `RELEASE/SRC/DATA/RECORDS/CSV_DEFAULT` at the top of each file:
CSV from `data/runs_reported.csv` (or the first argument), JSON/npz/csv from `data/derived/`, run records from `data/run_records/<experiment>/<runs_dir>/`.
Training histories (`<tag>_hist.npz`, supplementary archive 1 `skyrmion_histories.zip`, all 1,398 runs) and saved models (`<tag>_model.pt`, archive 2 `skyrmion_models.zip`, 323 runs) are expected in the same
`run_records/<experiment>/<runs_dir>/` folders: unpack the archives into `data/run_records/`. Figures are written next to the script (`make_fig_relaxation.py` takes the output path as its second argument). The GPU scripts write their results to `data/derived/` again.
Scripts that need only the CSV and `data/derived/` (tables 1, 2, 4, 5, 6, 8, 10, 11, 12, the appendix B.1 checklist, figures 2, 3 and 6) run without the archives; figures 4 and 5, table 7 and `summarize_vzero_probe.py` need archive 1;
`compute_iso_data.py`, `headline_symmetry.py`, `analyze_local_minima_v2.py`, `highres_all.py`, `highres_and_stats.py`, `reeval_b1_models.py` need archive 2 and a GPU.
Output encoding: `classify_failures.py` prints subscript characters and forces UTF-8 on stdout; on a cp932 Windows console other scripts print ASCII only.

## Environment (versions the package was verified with)
Python 3.10.12, PyTorch 2.10.0+cu128 (CUDA 12.8, cuDNN 9.10.2; driver 570.211.01), numpy 2.2.6, **scipy 1.15.3**, matplotlib 3.10.9, scikit-image 0.25.2, pykan 0.2.8 (reference implementation only).
All runs were made in this one environment, except the two re-runs of appendix A.4 (RTX 3060, PyTorch 2.14.0+cu126; see `code/experiments/2026-10-01_vzero/README.md`).
* **scipy:** the spherical harmonics in `headline_symmetry.py` are computed in `code/analysis/multipole.py` with `scipy.special.sph_harm_y(l, m, theta, phi)` (theta = polar angle, phi = azimuth; available since scipy 1.15). The function `sph_harm(m, l, phi, theta)` was deprecated in scipy 1.15 and has been removed from later releases; `multipole.py` falls back to it only on scipy < 1.15. `python3 multipole.py` runs a self-test (explicit Y_l^m, a test density with S_3 = 1/4π, rotation invariance, the theta/phi swap).
  With scipy 1.14.1 (fallback branch), 1.15.3 and 1.18.1 the twelve printed values of table 3 are the same. Run on a CPU, the scripts differ from the stored `derived/headline_symmetry.json` by ≤ 4×10⁻⁸ in S_l and ≤ 5×10⁻⁶ in the inertia eigenvalues (single-precision difference between CPU and GPU in the network evaluation).
* numpy ≥ 2 is required only by the pickled npz files (`derived/*.npz`, `*_hist.npz`); the CSV-only scripts run on any Python 3.
GPU: one NVIDIA RTX 6000 Ada. `code/src/models.py` contains our own B-spline KAN ("EffKAN", written after the efficient-kan design), a tanh/SiLU/GELU MLP,
a Fourier-feature MLP, and wrappers for pykan and FastKAN (FastKAN runs are reported in appendices A.2 and A.5; the KAN of the paper is EffKAN).

## Re-training (table 12 row → driver)

A driver writes `<tag>.json` (and `<tag>_hist.npz`, `<tag>_model.pt` where they are saved) to its own folder, `code/experiments/<experiment>/<runs_dir>/`, the same relative path as in `data/run_records/`. A run whose JSON is already in the output folder is not trained again. The record of every run holds its complete settings (`config`); for all 1,398 runs the settings that the drivers below pass to `train_one` equal the `config` of the record.

## Reproducibility notes
* **Standard deviations.** Every spread over seeds in the manuscript (the standard errors of table 1, the error bars of figure 2 and the three medians in its caption, table 10) is the **sample standard deviation, sum of squares divided by N−1** (`statistics.stdev`). The population value (`pstdev`, divided by N) is 10.6 % smaller at N = 5.
* `runs_reported.csv` carries the training configuration of every run, including `w_origin`, `soft_scale`, `lump_spread`, `lump_max_r`. **One run (`2026-08-28_B3_ansatz_free/runs_seeded2`, the imprinted run of figure 5) was trained before the clamp `lump_max_r` existed** (the key is absent from its `config`, shown as an empty cell): re-running it with the current code applies the default clamp 2.5 and can move the initial lumps. Its JSON record holds the complete `config` as it was.
* Same code, same seed (section 7.4): of the thirteen re-runs, nine reproduce the record bit for bit; the other four differ in the energy by 2.1e-8 (two runs), 1.6e-5 and 1.5e-4. The thirteen re-runs are the row `repro13` of table 12 (drivers `exp_determinism_check.py` and `repro_check.py`).
* The anchored 1D profile: `check_base_profile.py`/`.json` (E0 = 2.416270 from the 1D reduction and on the 48×28×36 and 80×44×60 grids).
